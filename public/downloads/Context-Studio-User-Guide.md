# ProcGen Context Studio: Official Configuration & User Guide

Welcome to the **Omni-Agent Logic Controller**. The Context Studio allows procurement managers, category leaders, and admins to define strict boundaries, financial guardrails, and behavioral rules for all ProcGen AI agents without writing a single line of backend code.

---

## 1. The 4-Stage Workflow

To ensure safe enterprise deployment of AI agents, the Context Studio enforces a 4-stage lifecycle:

1. **Bootstrap (Build context repos):** 
   Initialize a new configuration file (YAML format) targeted at a specific agent (e.g., Niti, Tark). Define the scope, rules, and logic.
2. **Simulate (Run evaluations):** 
   *(Coming in v2.0)* Test your rules against historical mock-negotiations to see how the agent would react in a sandboxed environment.
3. **Deploy (Push to agents):** 
   Click the **Deploy** button. The active rule is instantly pushed to the global database and takes effect immediately on all live agent interactions.
4. **Observe (Traces & drift):** 
   *(Coming in v2.0)* Monitor live agent transcripts to ensure they are strictly adhering to the YAML rules without hallucination or logic drift.

## 2. Configuration Parameters & Syntax

The studio uses a simple **YAML** structure. Below is the exact schema and allowed parameters you should use when defining agent logic.

### Required Fields

*   **`definition:`** (String) 
    The high-level name of the strategy (e.g., "Aggressive Baseline", "IT Software Renewals").
*   **`description:`** (String) 
    A human-readable explanation of what this logic file is meant to achieve.
*   **`scope:`** (Dictionary) 
    The boundaries of where this rule applies.
    *   `regions:` [Array] e.g., `[Global]`, `[APAC, EMEA]`
    *   `target_discount_percentage:` [Number] e.g., `15`
    *   `max_budget_buffer:` [Number] e.g., `10`
*   **`rules:`** (Array of Strings) 
    The exact natural-language commands the AI must obey. 

### Example: Strict Negotiation Configuration

```yaml
definition: "Hardware Aggressive Baseline Strategy"
description: "Forces Niti to negotiate firmly below market price for laptops."
scope:
  regions: [North America, EMEA]
  target_discount_percentage: 20
  max_budget_buffer: 5
rules:
  - "Never accept the initial offer under any circumstances."
  - "Always demand Net 60 payment terms."
  - "If the vendor refuses Net 60, immediately request a 5% further discount."
  - "Do not agree to multi-year lock-ins unless the discount exceeds 25%."
```

## 3. Agent Targeting

When initializing a new context file, you must specify the **Target Agent**. The system currently supports:

*   **Niti:** Handles live Vendor Negotiations and pricing pushback.
*   **Anveshan:** Handles deep web sourcing, RFP generation, and supplier discovery.
*   **Tark:** Handles automated Purchase Order (PO) creation, approvals, and contract logic.
*   **Garuda:** Handles real-time risk, supply chain monitoring, and ESG compliance.
*   **Jarvis:** The global co-pilot for internal employees navigating the portal.

> **Important:** Rules are agent-isolated. A rule deployed to Niti will *never* affect Tark's behavior.

---

## 4. Best Practices for Successful Deployment

1. **Keep rules mutually exclusive:** Do not write conflicting rules (e.g., "Always accept the lowest price" AND "Only accept SOC-2 compliant vendors even if more expensive"). The AI may hallucinate trying to resolve the conflict.
2. **Use precise metrics:** Instead of writing "Try to get a good discount", write "Demand a 15% discount minimum."
3. **Always click Deploy:** Auto-save only saves your draft. The agent will not consume the new logic until you press the **Deploy** button in the top right corner.
